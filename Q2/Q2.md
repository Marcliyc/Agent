# Q2 - Agent-Driven Feature Research System for Financial Time-Series Classification

## 1. Problem Definition
本方案选择 **方向 A（自动化特征工程）**，目标是构建一个可审计、可复现、泄漏安全的 Agent 系统，从 `X1~X300` 中筛选 Top 50 特征，并在时序切分下通过分类任务验证效果。

关键风险与要求：
- 金融时序场景必须避免 look-ahead bias。
- 特征筛选不能只看单一指标，需要兼顾有效性、稳定性、数据质量、冗余。
- 需要保留 Agent 决策日志与异常处理记录。

## 2. System Architecture

```text
Planner Agent
   ├── Label Screening
   ├── Leakage-safe Split Plan
   └── Task Decomposition

Diagnosis Agent
   └── Missing / Outlier / Skew / Stability / Predictive analysis

Cleaning Agent
   └── Impute / Winsorize / Transform / Drop decisions

Selection Agent
   └── Multi-view scoring + redundancy control + Top50 ranking

Executor (Guarded)
   ├── Run generated code
   ├── Retry on failures
   └── Persist logs and outputs
```

模块落地在：
- `Q2/code/src/agent/*`
- `Q2/code/src/features/*`
- `Q2/code/src/modeling/validate.py`
- `Q2/code/scripts/run_q2_pipeline.py`

## 3. Prompt Design

### Planner Agent (system prompt)
> You are a quantitative research planning agent for financial time-series modeling...

职责：读取 schema，筛选标签，定义时序切分，规划后续 Agent 顺序。

### Diagnosis Agent (system prompt)
> You are a feature diagnosis agent...

职责：按特征输出结构化诊断（缺失、异常、偏度、稳定性、预测性）。

### Cleaning Agent (system prompt)
> You are a feature cleaning agent...

职责：将诊断映射到可执行清理动作（填补、截尾、变换、删除）。

### Selection Agent (system prompt)
> You are a feature selection agent for financial time-series classification...

职责：综合打分并做冗余剔除，输出 Top 50 和选择理由。

## 4. Workflow
1. 加载数据（优先 `data/data.pq`，回退到 `split_chunk_*.pq`）
2. 进行时间先后切分（70/15/15）
3. 做 leakage check（train max ≤ valid min ≤ test min）
4. Label screening：从 `Y1~Y12` 自动选二分类标签
5. Diagnosis：输出 `feature_diagnosis.csv`
6. Cleaning：输出 `feature_cleaning_log.csv`，并生成清理后的数据
7. Evaluation：计算冗余惩罚与综合分 `FinalScore`
8. Selection：输出 `selected_top50.csv`
9. Validation：比较 raw_all / cleaned_all / agent_top50 / random_50 的分类指标（AUC, Precision, Recall, F1）
10. 持久化运行日志与元信息

## 5. Scoring Formula

设：
- `PredictivePower`：特征与标签 Spearman 绝对相关
- `Stability`：按 `trade_date` 分组均值波动的逆函数
- `RedundancyPenalty`：与其他特征高相关（>|0.9|）计数
- `DataQualityPenalty`：missing_rate + outlier_rate

```text
FinalScore =
  0.55 * PredictivePower
+ 0.30 * Stability
- 0.10 * RedundancyPenalty
- 0.05 * DataQualityPenalty
```

## 6. Exception Handling / Robustness
- Executor 统一封装运行步骤，失败可重试并记录 traceback。
- 任一步失败会记录 `step`, `success`, `output_summary`, `error`。
- 标签筛选失败（找不到二分类标签）直接抛错终止，保证结果不含隐式假设。
- 清理方案严格在 train 拟合参数并作用到 valid/test，避免泄漏。
